Architecture du fil rouge — taskflow

Formation Django avancé (Dawan) · application support construite pas à pas · Django 6.1 · annexe technique — carte des branches et des étapes

Le dépôt est organisé en étapes numérotées (etape-X.Y) sur la branche main, et en branches de démonstration demo/* qui partent chacune d'un tag et n'ajoutent que leur fonctionnalité (sans reprendre la suite de main). Repère rapide des phases : 1-2 = J1, 3 = J1/J2, 4 = J2, 5 = J3, 6-7 = J4.

La phase 6 (démos avancées) et les sous-étapes 2.x.y vivent sur des branches demo/*.

Branches de démonstration

demo/nouveautes-6x — part de etape-2.1

Nouveautés récentes de Django appliquées au modèle Task / Assignment, une par sous-étape :

  • etape-2.1.1 db_default (Django 5.0) sur Task.is_billable.
  • etape-2.1.2 CheckConstraint (Django 5.1) sur Task.progress (0–100).
  • etape-2.1.3 Index composite + partiel sur Task.
  • etape-2.1.4 CompositePrimaryKey (Django 5.2) sur Assignment — et ses limites (pas cible de FK, admin partiel), d'où le choix de main de garder une table d'association classique.

demo/modelisation-avancee — part de etape-2.1

  • etape-6.3 Enums riches et champs supplémentaires (ArrayField, DateRange). Runtime : PostgreSQL.

demo/admin-avance — part de etape-2.2

  • etape-2.2.1 Administration avancée : visibilité métier via get_queryset (un superadmin voit tout ; un membre du staff ne voit que ses projets — owner ou membre d'équipe — et ses tâches) et get_fieldsets sur-mesure (jeu complet pour le superadmin, vue allégée pour le staff, avec plusieurs champs par ligne). Test autonome fourni.

demo/mptt — part de etape-2.2

  • etape-6.2 Arbre tâches / sous-tâches : Task devient MPTTModel (champ parent), admin arborescent MPTTModelAdmin. Runtime : django-mptt.

demo/polymorphic — part de etape-2.2

  • etape-6.1 Hiérarchie polymorphe : Task parent, classes filles Anomaly / Action / Improvement ; admin parent + enfants avec filtre polymorphe. Runtime : django-polymorphic.

demo/admin-addons — part de etape-2.4

Extensions tierces de l'admin, une par sous-étape (un paquet chacune) :

  • etape-2.4.1 Filtre déroulant par projet (django-admin-list-filter-dropdown).
  • etape-2.4.2 Tri des statuts par glisser-déposer (django-admin-sortable2).
  • etape-2.4.3 Import / export CSV des tâches (django-import-export).
  • etape-2.4.4 Filtre par plage de dates d'échéance (django-admin-rangefilter).
  • etape-2.4.5 Filtre multi-sélection de priorité (django-more-admin-filters).

Runtime : les 5 paquets admin ci-dessus.

demo/realtime — part de etape-5.3

  • etape-6.4 Kanban temps réel (Django Channels) : consumer WebSocket BoardConsumer, diffusion des changements au groupe d'un projet. Runtime : serveur ASGI daphne.

demo/celery — part de main

  • etape-celery Notification e-mail asynchrone du owner à la création d'un projet : signal post_save sur Project → tâche Celery send_project_created_email (.delay()). Alternative « classique » aux tâches natives django.tasks de main. Runtime : celery + Redis + un worker (celery -A config worker).

demo/cache — part de main

  • etape-cache Trois stratégies de cache Redis sur deux bases distinctes : cache bas niveau d'un agrégat coûteux (cache.get_or_set, DB 1), fragment de template ({% cache %}, DB 1), page entière (@cache_page, DB 2). Runtime : django-redis + Redis.
